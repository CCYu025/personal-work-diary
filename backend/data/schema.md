# 個人工作日誌 — 資料結構說明（資料契約）

> 就算這個 App 未來停用或重寫，只要這份說明和 `data.json` 還在，資料就讀得懂。
> 資料的「意義」寫在這裡，不寫在程式碼裡。

## 資料放在哪裡

實際位置由 `.env` 的 `DATA_DIR` 指定：

```
<DATA_DIR>/
 ├─ data.json                   ← 正式資料（唯一事實來源，App 讀寫的就是這份）
 ├─ 個人工作日誌_匯出.xlsx        ← 按「匯出 Excel」產生的快照，給人看的
 └─ 個人工作日誌_精簡版.xlsx      ← 搬遷來源（原本手填的 Excel），App 從不改它
```

真實資料不進 git（見 `.gitignore`）。repo 裡只有 `backend/data/example/data.json` 這份虛構的範例。

## 最外層

```json
{
  "_meta": { "schemaVersion": "1.0", "app": "個人工作日誌", "savedAt": "2026-09-30T08:00:00.000Z" },
  "projects": ["MES", "機械手臂", "CCD", "行政", "其他"],
  "todos": [],
  "logs": []
}
```

- `schemaVersion`：欄位有調整時往上加。讀取程式要能容忍「舊資料沒有新欄位」。
- `projects`：專案的**預設順序**（從原本 Excel「選項」頁搬來）。畫面上的專案清單 =
  這份清單 ＋ 待辦／日誌裡實際用過的專案。**不是固定清單**，打一個新專案名稱就會自動出現。

## `todos`：待辦（對應 Excel「待辦」頁）

一件事一筆，狀態變了就改這一筆。

| 欄位 | 型別 | 必填 | 規則 | Excel 欄位 |
|---|---|---|---|---|
| `id` | 數字 | 是 | 遞增流水號 | — |
| `created` | `YYYY-MM-DD` | 是 | 新增時預設今天 | 建立日 |
| `project` | 字串 | 是 | 自由文字 | 專案 |
| `content` | 字串 | 是 | | 內容 |
| `status` | 字串 | 是 | `未開始`／`進行中`／`等待中`／`完成`／`取消`（固定） | 狀態 |
| `due` | `YYYY-MM-DD` 或 `null` | 否 | `null` = 沒有期限 | 期限 |
| `done` | `YYYY-MM-DD` 或 `null` | 否 | 見下方規則 | 完成日 |
| `note` | 字串 | 否 | 空字串 = 沒填 | 備註（卡關／下一步） |
| `updatedAt` | ISO 時間 或 `null` | 否 | `null` = 沒改過 | — |

**完成日規則**：狀態改成「完成」而且沒填完成日 → 自動填當天；狀態改成「完成」以外 → 清空完成日。
例外：從 Excel 搬過來的舊資料，原本沒填完成日就維持 `null`，不拿搬遷那天冒充。

**逾期**：有 `due`、`due` 早於今天、狀態不是「完成」也不是「取消」。跟原本 Excel 的條件格式同一條規則。

**為什麼 `status` 固定、`project` 開放**：狀態是這個 App 自己定義的管理維度；
專案是現實世界的東西，隨時會多一個，寫死只會一直落後。

## `logs`：日誌（對應 Excel「日誌」頁）

每天做了什麼就記一筆，可以修改、刪除（2026-09-30 決定：方便改錯字）。

| 欄位 | 型別 | 必填 | 規則 | Excel 欄位 |
|---|---|---|---|---|
| `id` | 數字 | 是 | 遞增流水號 | — |
| `date` | `YYYY-MM-DD` | 是 | | 日期 |
| `project` | 字串 | 是 | 自由文字，跟 `todos.project` 共用同一份清單 | 工作類別 |
| `content` | 字串 | 是 | | 工作內容 |
| `start` | `HH:MM` 或 `null` | 否 | 24 小時制 | 欄1（例：`0800-1700` 的前半） |
| `end` | `HH:MM` 或 `null` | 否 | 兩個都有時不能早於 `start` | 欄1 的後半 |
| `note` | 字串 | 否 | | 問題／明日計畫 |
| `updatedAt` | ISO 時間 或 `null` | 否 | | — |

原本 Excel 的「欄1」其實是時段，搬遷時拆成 `start`／`end`。看不懂的時段原文會放進 `note`，
格式是 `（原時段：…）`，不會默默丟掉。

時段**不拿來加總工時**：像「機械手臂 08:00–17:00」這種整天待命的紀錄，會跟當天其他工作重疊，
加起來沒有意義。

## 匯出的 Excel

`個人工作日誌_匯出.xlsx` 有「待辦」「日誌」兩張表，欄位跟原本的精簡版一樣（「欄1」改名「時段」），
條件格式也一樣（逾期紅、等待中黃、完成／取消灰）。這是快照，App 不會回頭讀它。
